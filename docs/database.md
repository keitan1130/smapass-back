# データベース

証明書は端末UUIDにひも付く最新観測値と全期間のログから表示する。発行済みスナップショットを保存する構造は廃止した。現行スキーマは [初期定義](../db/migrations/000001_initial_schema.up.sql) 1本。

| テーブル | 役割 |
| --- | --- |
| `devices` | UUID主キー `id`・一意な登録IMEI・持ち主の公開設定 `visibility`・作成日時 |
| `device_ownerships` | `device_id` にひも付く登録者の期間と最終検証済みログ受信時刻。3日ルールと権限に必要 |
| `device_keys` | 期間ごとの鍵、非公開attestation、鍵の失効履歴 |
| `device_logs` | 署名対象の正本、ハッシュ、前ハッシュ、署名、連番。更新・削除禁止 |
| `device_specs`, `device_status` | 元ログから作る最新表示・履歴用の投影 |
| `app_installations`, `app_tokens` | ログインなしの端末認証。トークンのハッシュと更新・再利用検知 |
| `key_registration_challenges` | 初回登録・鍵交換の期限付きチャレンジと消費状態 |
| `anchors`, `log_anchors` | 検証APIが返すチェーン・Merkle情報。チェーン送信自体は未実装 |

最新値と履歴は全登録期間を対象にし、端末UUIDと端末全体の連番を引き継ぐ。関連テーブルはIMEIを複製せず、`device_id` の外部キーで参照する。過去の鍵は署名検証に必要なので削除しない。過去の登録期間・更新済みトークンも権限と再利用検知に必要。`canonical_payload` のUTF-8が署名の正本であり、JSONBから作り直さない。DBトリガーはログの連番・前ハッシュ・現登録と鍵の有効性を検査する。署名はアプリ層で検証し、検証済み受信時刻で3日ルールを更新する。

スペックと状態の最新表示は、それぞれ元ログの `collected_at` 降順・同時刻は `seq` 降順で選ぶ。記録の受信・保存順が計測時刻と前後しても、古い観測値で最新表示を置き換えない。履歴・署名の連結・次の連番は保存順のまま維持する。


移行方法と旧DBの扱いは [db/README.md](../db/README.md)。UUID主キーの定義は初期マイグレーション1本にまとめる。既存DBを自動で初期化・変換しない。

1登録で扱うIMEIは1個。`devices.id` のUUID主キーと `imei` の一意制約で1対1を保証する。鍵交換・登録終了・持ち主交代でも端末行を維持し、UUIDを作り直さない。

公開APIは `public_devices` ビューを使い、非公開かつ再登録できない端末を除外する。設定は初回・持ち主交代で `private`。現在の登録なし、または最終検証済みログ受信（未受信なら登録開始）から72時間以上なら公開扱い。公開設定の更新は活動時刻・署名済みログを変更しない。詳細は [公開設定](api.md#公開非公開)。
