# UUID による端末・登録者管理

## 識別と公開入口

端末はランダムUUIDの `devices.id` を主キーとする。鍵・計測ログ・状態・登録期間・アプリ認証は `device_id` へひも付ける。IMEI全桁（15桁の文字列）は初回登録・再登録・検索のための一意な属性として `devices` に保持する。登録はIMEI1個のみで、公開UUIDと1対1に対応する。他のIMEIを後から追加・統合する機能は設けない。

証明書は `GET /api/devices/{id}` の最新観測値と全登録期間の履歴を表示する。WebページとQRは `/certificates/{id}` を入口にする。Go APIはHTMLを生成しない。

持ち主が替わっても同じ端末UUIDへ記録を追加し、最新状態・全履歴を保持し、公開設定と3日ルールに従って参照する。所有者の識別情報・認証情報・attestationは公開しない。

## API

利用者のアカウントやログインは作らない。最初にチャレンジを取得し、`POST /api/auth/devices` へ IMEI と Android の公開鍵・attestation・所有確認用署名を送り、アプリ用の認証情報を取得する。鍵の登録・検索・失効は端末用アクセストークンを持つアプリだけが使う。登録者はサーバーが管理するアプリ登録から決まり、JSON や任意の所有者ヘッダーからは受け取らない。

```http
POST /api/devices
Authorization: Bearer <access token>
Content-Type: application/json

{"device_id":"22222222-2222-4222-8222-222222222222","public_key":"-----BEGIN PUBLIC KEY-----\n...\n-----END PUBLIC KEY-----\n","proof":{"challenge_id":"<チャレンジID>","certificate_chain":["<DERをBase64>","<中間証明書・ルート>"],"signature_der":"<署名DERをBase64>"}}
```

- 初回登録・再登録はIMEI1個。15桁の数字とチェックディジットを検査する。登録後の操作では `device_id` を指定する。別IMEIの追加・統合はしない。
- 鍵は P-256 の公開鍵（PEM SubjectPublicKeyInfo）、署名方式は ES256。形式を検査して保存する。Google の信頼ルート、失効状態、ハードウェア鍵、起動状態、アプリ情報、チャレンジと所有確認用署名を検証する。計測ログの署名対象も端末UUIDを使う。IMEI 自体の検証範囲は通常の key attestation と区別する。
- 同じ登録者が同じ鍵で再送した場合は同じ登録期間と鍵を返す。同じ登録者の鍵交換では旧鍵を失効して履歴を保持する。
- 応答は `device_id`、`visibility`、`ownership_id`、`registered_at`、`last_verified_log_at`、`reclaimable_at`、`key_id`。所有者の認証情報は返さない。

```http
POST /api/devices/lookup
Authorization: Bearer <access token>
Content-Type: application/json

{"device_id":"22222222-2222-4222-8222-222222222222"}
```

現在そのアプリに登録され、公開鍵の登録が完了した端末だけを返す。他人の端末と不存在はともに404。公開証明書のデータは `GET /api/devices/{id}` を使う。

## 別の登録者への切り替え

前の登録者の最後の**検証済み計測ログのサーバー受信から3日（3×24時間）以上**経過したら再登録できる。ちょうど3日経過した時点から許可する。ログ未受信の場合は登録時刻を基準にする。

検索、認証情報の更新、同じ登録者の鍵の再登録・鍵交換、未検証ログでは活動時刻を更新しない。クライアントの取得日時は待機期間の判定に使わない。

切り替えでは旧登録期間・認証情報・旧鍵の失効と、新登録期間・認証情報の発行を1トランザクションで行う。新しい公開鍵も初回登録時に同時に保存する。過去のログ・証明書・鍵は残す。IMEI のロックと端末行のロックで同時登録を直列化し、同時に2人へ切り替わらないようにする。ログの受信も同じ端末行をロックし、切り替え後の旧登録者のログを拒否する。

3日経過だけでは自動失効しない。別の登録者が再登録した時点で操作権限を切り替える。履歴を保持したまま、新しい持ち主の設定は非公開に戻す。

別の登録者へ切り替わる前に元の端末が通信を再開した場合は、元の登録期間と鍵を使い続けられる。署名検証済みの新しいログが届いた受信時刻から、再び3日間を数える。アクセストークンが期限切れなら有効なリフレッシュトークンで更新する。認証情報の更新だけや保存済みログの再送では期間を延長しない。別の登録者へ切り替え済みの場合は旧認証情報と旧鍵を復活させず、新しい登録者の権限を守る。

ログ受信時は署名検証に成功した場合だけ `signature_verified_at` を設定し、サーバー受信時刻で3日ルールの活動時刻を更新する。

## 現在の登録者による手動失効

売却や譲渡の際は、現在の登録者が次の API を呼ぶと3日待たずに登録を終了できる。

```http
POST /api/devices/22222222-2222-4222-8222-222222222222/revoke
Authorization: Bearer <access token>
```

成功は204（本文なし）。登録したUUIDでその端末の登録を終了する。認証済みの現在の登録者だけが操作でき、別端末の有効なトークンでの操作や不存在は404、不正な UUID は400、不正・失効済み・旧登録者のトークンは401となる。

登録期間の終了、利用中の鍵と認証情報の失効を1トランザクションで行う。登録終了中は公開状態・履歴を参照でき、次の利用者は 新しいチャレンジ・鍵・検証証跡を用意し、`/api/auth/devices` ですぐ再登録できる。旧鍵によるログは受け付けない。旧登録者が再送しても、新登録者の登録は失効しない。

過去のログ・ハッシュ・署名は削除しない。認証情報だけの失効は `/api/auth/revoke`。証明書単位の失効は行わない。

## 認証との接続

ログインなしの発行・更新・失効、Android の呼び出し順と、書き込み時の権限確認は [authentication.md](authentication.md) を参照。外部 JWT の検証設定は使わない。再登録の3日ルールは `/api/auth/devices` で判定し、鍵登録 API ではその認証情報の対象端末だけを操作できる。

## 既存データの移行

現行スキーマは初期定義1本。新規DBの初期化・既存DBの保護・バックアップは [db/README.md](../db/README.md) を参照。通常の起動で旧DBを初期化しない。

公開表示はUUIDを使う。IMEIでの検索は `/api/devices/search?imeis=...`、表示は `/api/devices/{id}` と `/api/devices?ids=...`。所有者・鍵が替わってもUUIDは変わらない。

初回登録・持ち主交代後は非公開。公開設定は [公開・非公開API](api.md#公開非公開) を参照。登録終了中・再登録可能な間は公開し、持ち主交代で非公開に戻す。
