# スキーマ

テーブル・制約・トリガーは `migrations/000001_initial_schema.up.sql` の1本。新規DBには `migrate up` で適用する。UUID主キーへの変更もこの初期定義にまとめ、追加マイグレーションや既存データの変換処理は設けない。

`devices.id` はランダムUUIDの主キーで、APIの公開IDと共通。`devices.imei` は15桁の文字列・一意な登録属性。登録期間・鍵・ログ・表示用投影・アプリ認証は `device_id` を参照する。チャレンジは初回登録前のみIMEIを保持し、鍵交換ではUUIDを保持する。

初期定義を変更しても適用済みDBは更新されない。既存DBの自動削除・再作成はしない。`down-one` は全テーブルを削除するため、使い捨てDB以外では実行しない。

`devices.visibility` は持ち主の設定で初期値は `private`。公開読み取りは `public_devices` ビューへ統一する。現在の登録なし、または検証済みログ受信（未受信なら登録開始）から72時間経過した端末は設定にかかわらず公開になる。ビューも初期定義1本に含む。

デモは `seeds/development.sql` の手動投入のみ。架空ログを署名検証済みとして扱わない。
