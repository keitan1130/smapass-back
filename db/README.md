# スキーマ

現行のテーブル・制約・トリガーは `migrations/000001_initial_schema.up.sql` の1本。旧マイグレーションは保管しない。新規DBには `migrate up` で適用する。`down-one` は全テーブルを削除するため、使い捨てDB以外では実行しない。

この整理は新規DBの基準を作り直す変更。旧DBのバージョン番号やスキーマを自動で新基準に合わせない。既存の `devices` に公開UUID列 `public_id` がない場合、または鍵登録チャレンジが複数IMEIを保持する構造の場合は、up/downを拒否する。構造が対応していればバージョン2以降も拒否しない。将来の変更は適用済みの初期定義を書き換えず、連番のup/downを追加する。移行状態・dirty状態の検証と実際の適用はgolang-migrateに任せる。未対応DBを継続使用する場合には、バックアップとデータ移送・専用の移行手順が別途必要。バージョンの強制変更だけで移行したことにしない。

今回の編集で既存DBへの適用やボリューム削除は行っていない。デモは `seeds/development.sql` の手動投入のみ。架空ログを署名検証済みとして扱わない。

副IMEIテーブルとチャレンジのIMEI配列列は初期定義から除去した。適用済みDBを自動削除・再作成しない。以前の複数IMEI構造のDBは起動前に拒否し、継続利用には別途データ移行が必要。
